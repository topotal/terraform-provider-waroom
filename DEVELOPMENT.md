# Developing the Provider

This document describes how to build, test, and develop the Waroom Provider.
For usage, see the [README](README.md).

## Requirements

- [Terraform](https://developer.hashicorp.com/terraform/downloads) >= 1.16
- [Go](https://golang.org/doc/install) >= 1.27
- [Task](https://taskfile.dev/)

## Dependency on `waroom-client-go`

The provider uses [`waroom-client-go`](https://github.com/topotal/waroom-client-go) to call the Waroom API.

It is pinned to a tagged version (currently `v0.0.0-alpha`) in `go.mod`. To update the pinned version:

```shell
go get github.com/topotal/waroom-client-go@<version>
go mod tidy
```

## Building

```shell
git clone git@github.com:topotal/terraform-provider-waroom.git
cd terraform-provider-waroom
task install
```

This builds the provider and puts the binary in `$GOPATH/bin`.

## Using the Provider Locally

To use a locally built provider, add a [development override](https://developer.hashicorp.com/terraform/cli/config/config-file#development-overrides-for-provider-developers) to `~/.terraformrc`:

```hcl
provider_installation {
  dev_overrides {
    "registry.terraform.io/topotal/waroom" = "<GOPATH>/bin"
  }
  direct {}
}
```

## Using a Local `waroom-client-go`

To develop against unreleased changes in `waroom-client-go`, override the pinned version with a [Go workspace](https://go.dev/doc/tutorial/workspaces).

Clone `waroom-client-go` next to this repository:

```text
.
├── terraform-provider-waroom
└── waroom-client-go
```

Then create a workspace in `terraform-provider-waroom`:

```shell
go work init . ./tools ../waroom-client-go
```

- `go.work` and `go.work.sum` are listed in `.gitignore`. They are local to each developer and must not be committed.
- Include `./tools` as well. Otherwise `task gen-docs`, which runs in `tools/`, fails because `tools/` is not part of the workspace.
- Before opening a pull request, release the change in `waroom-client-go` and bump the pinned version in `go.mod`. CI builds against the version in `go.mod`, not your local checkout.

## Adding a Resource or Data Source

Scaffolding can be generated with `cmd/tfgen`:

```shell
task gen:r name=<name>  # resource
task gen:d name=<name>  # data source
```

## Testing

Run unit tests:

```shell
task test
```

Run acceptance tests. They require the `E2E_WAROOM_API_KEY` and `E2E_WAROOM_API_ENDPOINT` environment variables.

> [!WARNING]
> Acceptance tests create real resources in the target Waroom environment.

```shell
export E2E_WAROOM_API_KEY="<your-api-key>"
export E2E_WAROOM_API_ENDPOINT="<api-endpoint>"
task test:acc
```

## Generating Documentation

Documentation in `docs/` is generated by [terraform-plugin-docs](https://github.com/hashicorp/terraform-plugin-docs) from the schema and `examples/`:

```shell
task gen-docs
```
